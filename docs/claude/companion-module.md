# Companion module

Moved out of `CLAUDE.md` unchanged. Read this before changing anything in `companion-module/`.

## Companion module (`companion-module-companionplayer`)

- Built for Companion 5.1.1 on module API 2.2 (`@companion-module/base ~2.2.2`, `@companion-module/tools ^3.2.0`, Node 22, ESM). Do not use `@companion-module/base` 1.15: it needs Companion 5.1.2+.
- Source: `src/main.js` (polls `/api/state` every 250 ms, refetches `/api/variables` and `/api/playlists` when `rev` changes), `actions.js`, `feedbacks.js`, `presets.js` (structure + presets; layered presets for the live and preview monitor buttons), `consts.js` (`SLOTS = 32`).
- Config fields: IP address, port, variable prefix (default `mp_`), poll interval.
- Module 2.7.8 (with the Live input): actions `input_armed` / `input_duck_now` (`/input/armed/<v>`, `/input/ducknow/<v>`), feedbacks of the same names plus `input_signal` / `input_ducking`, presets `liveinput_*`; the variables `input_armed/duck_now/signal/ducking` come from `/api/variables` like every other. Next free module number is 2.7.9 (rule above).
- Module 2.7.0: reads `player_version` from `/api/state`, compares major.minor with `MODULE_VERSION` (`src/consts.js`, keep equal to `package.json`) and logs one warning plus sets the module variable `version_match` (`ok` / `mismatch` / `unknown`). Nothing else changed. Package: `Module/companionplayer-2.7.0.tgz` (here `companion-module/`); the source zip no longer contains the `pkg/` build folder.
- Module 2.6.1: action `preview_volume` (set/up/down, uses `/preview/volume/...`) and presets `pv_vol_info`, `pv_vol_up`, `pv_vol_down`, `pv_vol_rotary`; the `preview_volume` variable comes from the player. No module support yet for a track's own crossfade time (`/<p>/<t>/xftime/<seconds|clear>`, `xfade` in `/api/playlists`).
- Module 2.6.0: monitor-preset gauges use `live_fader_l/r` / `preview_fader_l/r` with colour stops computed in `consts.js` (`taperPct`, a mirror of the player's `METER_STOPS`; keep them in step); new presets `meter_db`, `go_mode`; action/feedback `go_transition` for the web page's Go button (Take/Crossfade actions unchanged); legacy `*_level_*` variables kept and documented as legacy. Variables come from the player's `/api/variables`, so new player variables appear without module changes. `CHANGELOG.md` in the module source.
- End actions (module 2.5.0): actions `play_playlist`, `track_end`, `live_end` (the old loop actions mean loop forever); feedbacks `track_end`, `live_end` and the `once` / `stop` choices of `slot_state`; module-side variables `live_end` (NEXT/ONCE/LOOP/STOP) and `live_pass` ("1 of 2") derived from `/api/state`; presets `live_end`, `play_cued_list`, and `play_<p>` / `end_<p>_<t>` in each playlist section. Needs the player with `end_actions`. Source zip: `Module/companion-module-companionplayer-src.zip` (no `node_modules`; run `npm install` first).
- Dynamic variables `slot1_name` ... `slot32_name` and `slot_count` follow the playlist that holds the cue; "Cued playlist" presets and the `slot` action use them.
- **Module version vs player version (PROPOSED RULE, to be confirmed by the owner):** the module checks only major.minor against the player (`checkVersion`; `tests/test_module_version.py`), so during a 2.x.y line the module's patch number may run ahead of the player's (2.7.5 player with module 2.7.6 since rc2). Rule proposed so a later player 2.7.6 does not collide with a different module 2.7.6: (1) the module's patch number is its own counter: it only goes up and a number is never reused for different contents; (2) a player patch release does not need a new module and does not set the module's number; (3) when the module code changes, take the next number above the highest module ever published (so after module 2.7.6 the next module is 2.7.7, even if the player is still 2.7.5 or is 2.7.6); (4) a new minor line restarts both at x.y.0 (module 2.8.0 for player 2.8.0); (5) each release (and pre-release) notes name the module file and its SHA-256, and the module CHANGELOG says which player it needs. Nothing enforces (1) to (3) in code yet.
- Build and package: `npm install && npm run package` produces `companionplayer-<version>.tgz`. Bump `version` in `package.json` on every change, because Companion may refuse a re-import with the same version. Option values in module API 2.x arrive already parsed (no `parseVariablesInString`); use `isVisibleExpression` with `disableAutoExpression` on the referenced fields.
