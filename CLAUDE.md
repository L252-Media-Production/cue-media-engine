# Cue Media Engine (CueME)

Cue Media Engine (CueME): playlist audio player for live AV work (L252 Media Production), controlled from Bitfocus Companion and from its own web page. (The code and folders keep the earlier name: `cpl/`, `companionplayer`, `cp_`, `mp_`.) One Python file plus a `static/` folder of web files, no build step.

## Layout

| File | What it is |
|---|---|

The Companion module is a separate project (`companion-module-companionplayer`, see below).

## Where it runs

- **Production target:** Linux (Debian), headless, run as a systemd service, with audio out through a USB audio interface. Bitfocus Companion usually runs on the same machine; shell-command support must be enabled in Companion for buttons that run `systemctl`.
- **Windows:** supported for testing and portable rigs (pygame-ce).
- **macOS:** runs, but the memory readout is not implemented there.

## Run it

```
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
.venv/bin/python player.py
```

Web UI: `http://<host>:8080`. Defaults in `CFG`: `http_port` 8080, `osc_in_port` 9000, `companion_host` 127.0.0.1, `companion_osc_port` 12321, `var_prefix` `mp_`, `cache_mb` 768.

## Architecture

**Where the code lives (2.7.1):** the names below are unchanged; to find one, grep `cpl/`. Shared state is `cpl/state.py` (`from cpl import state as S`): containers (`playlists`, `library`, `decks`, `focus`, `FOLDER_*`, `LIBDIRS`, `ISSUES`, `DEV_MISSING`, `DURS`) are imported by name and never rebound; rebindable scalars exist only as `S.<name>` (`live_deck`, `pending`, `pending_n`, `cue_cleared`, `known`, `last_scan`, `rev`, `MONITOR`, `LAST_LOAD_ERR`, `boot_done`, `notify`). Hooks: `S.on_change` (run by `bump()`; `warm` registers `request_warm`), `S.on_save` (run by `save()` after `bump()`; `loudness` registers `request_loudness`), `S.notify` (= `push`, set by `legacy`, used by modules below it). A function that tests patch or that is registered in a hook is called as `module.func()` (`warm.request_warm()`, `loudness.request_loudness()`), never imported by name; the module aliases in `legacy` are `plm` (`cpl.playlists`), `libm` (`cpl.library`), `durm` (`cpl.durations`) because `playlists`/`library` are the state containers. A module never imports `cpl.legacy`; the allowed imports are the table in `docs/split-plan.md` 2.1 (`tests/gates/import_allowlist.json`). Nothing outside `cpl/clock.py` calls `time.monotonic/time/sleep`; tests install a fake clock with `clock.install()`.

- **Audio:** pygame mixer. A track must be decoded into RAM before it plays; MP3/OGG/FLAC are decoded in a helper process and handed over as raw PCM so the output never freezes. Decoded sounds live in an LRU cache (`_cache`, budget `cache_mb`); the tracks around the cue are warmed ahead of time.
- **Cue cost:** `_load` also computes the ducking key (`_key`, per-10 ms level) and the warm-up cuts trimmed tracks ahead of time (`_tcache`, keyed `(path, lo, hi)`, counted in `cache_mb`), so a cue and Play on Top never copy or analyse audio on the event loop. `cache_drop(path)` forgets everything derived from a file. Helpers: `atomic_write` (fsync), `log_once`, `spawn` (keeps background tasks referenced), `body(req)` (tolerant JSON body).
- **Decks:** the `Deck` class holds one playing track (`base`/`lo`/`hi` trim window, `fpos()` file position, duck multiplier, `end_fade_ms`). The main loop ticks every 50 ms.
- **End actions (per track):** `playlists[p]["end_actions"] = {file_id: "once"|"loop"|"stop"}` (default absent; replaces the old `loops` list, which `load` migrates, keeping `playlists.pre-endactions.json`). Helpers `end_of / set_end / is_loop / set_loop`; `END_ACTIONS` cycle default > once > loop > stop. The state is keyed by file id like trims: `lib_rename` remaps it and `move_track` carries it to another playlist. `_start` plays `loops=-1` (loop) or `loops=1` (once, `Deck.passes = 2`, only when starting from the In point and not on top); `Deck.update` ends after `duration * passes` (latched `one_pass` when switched away during pass 1), `remaining()` and `fpos()` are per pass, `pass_no()` for the Live hint. `stop` is checked at the top of `auto_advance`. `/api/playlists` has `end` and `loop`; `/api/state` has `live_end / live_pass / live_passes`.
- **Per-track crossfade:** `playlists[p]["xfades"] = {file_id: ms}` (absent = master `crossfade_ms`), `xfade_of / xfade_ms / set_xfade`; `xfade_ms(p, t, ms)` = explicit `?ms=` > the track's own time > master, used by `play_default`, `/<p>/<t>/xfade` and `/xfade`. `lib_rename` remaps it and `move_track` carries it. Command `/<p>/<t>/xftime/<seconds|clear>`; `/api/playlists` has `xfade` (ms or null). UI: `#foc_xf` under the Go toggle (`#gocol`, dimmed while `go_transition` is cut) (`updFocXf`, `focXfSave`), an `XF` badge on rows.
- **Trim (A/B):** per playlist entry. Fade or cut at B, A/B window shown with dimmed waveforms. `trim_of / trim_range / set_trim`. **Fade length at B:** optional `fade_ms` (100-10000 ms) in the same trim dict (dropped when there is no B; stored clamped to B - A; kept while the edge is Cut). `fade_ms_of(p, t)` = own value else `fade_default_ms()` (config `trim_fade_ms`, edited in Settings > Transitions via `/api/settings/transition` `trim_fade_s`); `_start` is the only place that sets `Deck.end_fade_ms` (live, Play on Top, trigger voice-overs, resume; seek keeps it, `Deck.update` still caps it at the played part). `/api/playlists` tracks have `fade_ms_eff`, `/api/state` has `live_fade_ms`, `POST .../trim` takes and returns `fade_ms`. Dialog: `TR.fade` (ms or null = default), `trFadeEff/trFadeSet/trFadeDef` (the fade field is a plain number input with the native spinner; no -/+ buttons, no `trFadeStep`), the same value drives the waveform wedge and `trAud`. The Settings save function is `tranSave` (it used to be a second `trSave`, which the trim dialog's function silently replaced). Tests: `tests/api/test_trim_fade.py`; dialog (no -/+ buttons, spinner, keyboard nudges, no clipping at maximum values in 3 skins x desktop/phone/touch): `tests/test_trim_dialog.py`. Number/time fields in the dialog and trigger rows get their width in `ch` plus an id-level padding (the generic button/select/input padding rule is more specific than a class). Trim dialog time bubble: `#trtip` / `#trcur` are fixed DOM overlays (no canvas redraw) driven by `trTip / trTipFor / trTipHide` from the `#trwf` pointer handlers (hover and drag; hides on leave, on touch release and on close); `trT` formats m:ss.s (h:mm:ss.s over an hour); `#tr_ph` shows the playhead, refreshed from `trDraw` via `trPh`.
- **Fade in at A (2.7.4):** the trim dict also holds `start: "fade"` (stored only for a fade-in; Cut is the default and absent) and `fade_in_ms` (100-10000, clamped to B - A or to the rest of the file, kept while the edge is Cut, a trim entry holding only these survives). `fade_in_ms_of(p, t)` = own value else `fade_in_default_ms()` (config `trim_fadein_ms`, 0 = none; Settings > Transitions via `/api/settings/transition` `trim_fadein_s`); `fade_in_start_ms(p, t)` = that only while `start == "fade"`. `_start` is the only place that applies it: `offset <= 0.05` (never `deck.fresh`), not paused, not under a crossfade (the crossfade is the fade-in), via `deck.start_fade(level, ms)` (the track on top fades up to its `top_track_pct` level; ducking meanwhile is at full depth, accepted); capped to the played part minus the out-fade; `Deck.fade_in_ms` is what it started with. Trigger voice-overs have `p = None`, so no trim and no fade-in. `/api/playlists` tracks have `fade_in_ms_eff`, `/api/state` `live_fade_in_ms` / `trim_fadein_ms`, `POST .../trim` takes and returns `start` and `fade_in_ms`. ## Control surface

- **HTTP:** `/api/live` is a server-sent-event stream for the web page (meters about 14 Hz, preview state 4 Hz, at most 16 open; the page closes it while the tab is hidden); the page otherwise polls `/api/state` once a second, one request at a time.  `GET /api/<command path>` runs a command and returns `{"result": ..., **snapshot()}`. Also `/api/state` (snapshot plus `live_pos`, `live_dur`, `live_in`, `live_out`, `live_fid`, `trim_fade_ms`, `health`, `mem`, `rev`, `preview`, `feedback`), `/api/variables`, `/api/playlists`, `/api/meters`, `/api/settings/top`, `/api/settings/folders`, `/api/devices`.
- **OSC out:** `push()` sends changed variables to Companion as `/custom-variable/<var_prefix><name>/value` (full resend every 5 s). The Companion module does not use this; it polls HTTP.
- **Command grammar** (`command(parts, ms)`): `/<p>/<t>` play; `/<p>/play` (first track, random when shuffling: `play_playlist`), `/<p>/<t>/loop[/0|1]`, `/<p>/<t>/end[/default|once|loop|stop]` (no value cycles; `fade|cut` still means the trim edge), `/in|out/<sec>`, `/end/fade|cut`, `/trim/clear`, `/xfade`, `/top`, `/cut`, `/toggle`, `/focus|cue`; globals `/next /prev /nextlist /prevlist /clear /take /xfade /cut /toggle /top /loop /mode/<m|next> /preview/<p>/<t>|focus|stop|pause|resume|playpause /solo[/0|1] /volume/<n|up[/n]|down[/n]|mute> /seek/<sec> /pause /resume /playpause /fadeout /stop /stopall /resend /rescan /device/<n|next|default> /duck/<threshold|ratio|attack|release|level>/<value|inc|dec>[/step] /duck/hold[/0|1]`. `?ms=` overrides the fade time. Play modes: `stop`, `loop_playlist`, `next_playlist`, `shuffle`.
- Variables are defined in `snapshot()` and documented in the `VAR_INFO` dict next to it. Playlist and track names are exposed as `pl<N>_name`, `pl<N>_count`, `pl<N>_t<K>`.

Nothing enforces (1) to (3) in code yet.

Option values in module API 2.x arrive already parsed (no `parseVariablesInString`); use `isVisibleExpression` with `disableAutoExpression` on the referenced fields.

## Testing

**Test harness (phase 1, `tests/`, see `tests/README.md`):** `python tests/run.py` starts a disposable player from a copy of `player.py` (own `cptest-*` folder, random ports 18200-18999, dummy audio, generated library, OSC sink instead of Companion), runs the pytest API/command/OSC suite in `tests/api/` and writes `tests/reports/<platform>-<date>/` (`report.md`, `results.json`, `junit.xml`; severity 1-4 per failed test). `--base-url` against an existing instance is refused unless it is a harness instance, or `--allow-remote --confirm-target HOST:PORT` is given. `tests/gen_controls.py` (reads `player.py` and assembles the UI from `static/`; control locations are `static/<file>:<line>`; run it with `PYTHONHASHSEED=0`, its call lists depend on the hash seed) + `tests/controls_meta.py` regenerate `tests/controls.csv` (every command word, route, OSC behaviour, variable and UI control; unknown ones are flagged UNCLASSIFIED): run it after changing the grammar, routes, variables or UI. The player reads `config.json` and all data from the folder of its own script, so run test copies from their own folder, never `python player.py` from a scratch cwd. `python tests/run.py` also runs `tests/engine/` (in-process tests of the audio engine with a fake clock: `harness/engine.py`, fades, auto-advance, ducking numbers, tick order) and `tests/api/test_resume.py` / `tests/api/test_audio_capture.py` (own instances: resume after a kill; the real rendered output captured with `SDL_AUDIODRIVER=disk`, marker `audio`, skipped where the disk driver is missing); `-m audio` / `-m "not audio"` select them. `tests/test_gates.py` and `tests/test_no_bare_state.py` hold the static gates (the latter also runs `test_state_identity.py` / `test_state_hooks.py` through `run.py`), `tests/tools/` the move verifier and the onset-capture diagnostic. `CPTEST_EXTRA_CONFIG='{"ffmpeg_path": "/nope/ffmpeg"}' python tests/run.py` runs the whole suite without ffmpeg (step 5 below; the deep format test skips). Playwright stays in stand-alone scripts (`test_trim_dialog.py` etc.); stress tests are not written yet.

**Page equality (regression check for the file split):** `python tests/test_pages_equal.py` (also run at the end of `tests/run.py`) starts a WAV-only instance, fetches `/`, `/help`, `/stage`, `/variables`, `/api/state`, `/api/playlists`, `/api/variables`, `/api/library`, normalises them (`tests/harness/golden.py`, documented in `tests/golden/README.md`) and compares their sha256 with `tests/golden/SHA256SUMS`. Any change of those pages or outputs fails it; if the change is intended, run `python tests/test_pages_equal.py --update` and commit the new golden files. **Baseline: `tests/reports/baseline-post-fixes/` (tag `post-fixes`) had 370 passed, 0 failed, 1 skipped (the memory readout is not implemented on macOS); the same tests now give 372 (two were added later), with the gap tests (tag `split-gap`) the full run was 464 passed, 0 failed, 1 skipped, and at 2.7.1 (tag `v2.7.1-rc1`, after the P4-P6 tests) it is 475 passed, 0 failed, 1 skipped (pytest; the stand-alone scripts are counted separately) (`tests/reports/baseline-split-gap/` holds the output; like `baseline-post-fixes` it is a local folder that git ignores). Any failure in `python tests/run.py` or in the stand-alone scripts is a regression**; compare with `grep -E '^(FAILED|SKIPPED)' <pytest output> | sort | diff - tests/reports/baseline-post-fixes/failed-and-skipped.txt`. The 38 failures of the first baseline (`tests/reports/baseline-pre-split/`, tag `pre-split`) were all fixed; see `docs/known-failures.md`. Tests copy the app with `harness.appcopy.copy_app(dest)` (player.py plus `cpl/` and `static/` when present); the device tests use the `CP_TEST_DEVICES=<folder>` hook in player.py (inert when unset).

Older ad-hoc method (still valid for one-off checks):

1. Start a test server: `SDL_AUDIODRIVER=dummy python3 -u -I player.py` in a scratch folder with a `config.json` such as `{"http_port":18130,"osc_in_port":18131}` and a `media/library/` holding a few short WAVs.
2. Drive it with `curl` against `/api/...`, and drive the page with Playwright (Chromium is installed in the cloud sandbox).
3. After changing the UI script, syntax-check it: `node --check static/app.js static/icons.js static/tour.js` (one file per call). A leftover line once broke the whole page this way. Then run `python tests/test_pages_equal.py` (it fails on purpose when the page changed; update the golden files only for an intended change).
4. Kill test servers in a separate shell call (`pkill -9 -f "[p]ython3 -u -I player"`); chaining `pkill` with other commands has ended the shell early.
5. ffmpeg tests: generate material with `ffmpeg -f lavfi` (sine/anoisesrc, mono/6ch/44.1k, junk and truncated files); test both with ffmpeg and with `"ffmpeg_path": "/nope/ffmpeg"` to prove the fallbacks.
6. For the module: run `node` against `src/*.js` with a mock instance (see git history of the module for the harness) while the test player is running.
7. Production readiness checklist: the "CompanionPlayer production readiness checklist" doc (soak, abuse, failure recovery).

## Conventions and gotchas

- **Gates (run by `tests/run.py`):** `tests/test_gates.py` (time only through `cpl.clock`, no function-local `cpl` imports, helpers import no app code, the import graph equals/contains-in `import_allowlist.json` and is acyclic, nothing imports `cpl.legacy`), `tests/test_no_bare_state.py` (no `global` of a shared name, no bare use of a moved scalar, `cpl.state` only as `S`, containers never rebound, `S.x =` only in the writer table, only the listed module-private names may be rebound with `global`, no by-name import of a patched function), `tests/test_state_identity.py`, `tests/test_state_hooks.py` (hooks are registered after the import and called in order), `tests/test_launchers.py`, `tests/test_module_version.py` (player 2.7.x + module 2.7.0 = ok). Moves between modules are proved with `tests/tools/verify_move.py` / `verify_step.py` (normalised AST) and done with `tests/tools/move_defs.py` / `state_rewrite.py`.
- **Release:** bump `APP_VERSION` (`cpl/config.py`), regenerate the golden hashes in their own commit (`python tests/test_pages_equal.py --update`, only the version fields may differ), update `CHANGELOG.md`, run the full suite twice, tag `vX.Y.Z-rcN` on the release branch. `dist/*.zip` is built with `git archive` and not committed.
- **Split workflow (branch `split`, plan `docs/split-plan.md`):** commits are prefixed with the step (`P4:`, `P5/P6:`, `Tests:`). After creating a `split-*` tag, push the branch and that tag only: `git push origin split` and `git push origin <tag>` (set the upstream once with `git push -u origin split`). Push only `split`, `split-*` tags, the `release/*` branch of a release and its `vX.Y.Z-rcN` tags: never `main` (see the promotion rule below), never `--force`, never delete or move a pushed tag; if a pushed tag would have to move, stop and ask. If a push fails or hangs (`git ls-remote` hung once), report it and carry on; do not retry with force. Report the pushed refs in each stop report. To test a split build on the NUC or Windows the branch/tag must be pushed (see the deploy note in the plan).
- **Promotion rule (main):** `main` is only ever updated by a fast-forward promotion of a tested `release/*` branch (`git push origin <tested-commit>:refs/heads/main`, never forced), on the owner's explicit request, and the release tag `vX.Y.Z` (annotated, on that same commit) is created at the promotion and pushed alone. First verify that `origin/main` is an ancestor of the release commit, that the `-rcN` tag and the release branch tip are the same commit, and that the remote has no `vX.Y.Z` yet. 2.7.2 was promoted this way (`077cabb` = `v2.7.2-rc4` = `v2.7.2`).
- Line endings: `.gitattributes` has `* text=auto eol=lf`, so `static/` and `player.py` are LF in every checkout (only `*.bat` / `*.ps1` are CRLF). As a second guard `_static()` turns CRLF into LF when it reads a file, so a copy with CRLF (autocrlf off in the repo, or files copied by hand on Windows) still assembles the identical page and the `//@include` / `<!--@include` marker checks still match; LF files are read byte for byte. Test: `tests/test_static_crlf.py` (CRLF copy of `static/`, golden hashes of `/`, `/help`, `/stage`, `/variables`).
- Version: `APP_VERSION` in player.py is the one product version (Settings footer line `CompanionPlayer x.y.z`, `/api/state` `version` and `player_version`, Companion variable `player_version`). The Companion module has the same major.minor and warns (log + variable `version_match`) when they differ. Bump it together with the module version and `CHANGELOG.md`.
- `player.py` plus `static/`: no build step. The UI is plain files in `static/` (no Python string quoting any more); keep `app.js` a classic script (148 inline `on*=` handlers need globals) and the include markers once each.
- Update `README.md` and the in-page Help (`static/help.html`) and tour (`static/tour.js`) when behaviour changes.
- The page keeps no state in the browser except small per-viewer conveniences (theme, tour-seen flag in `localStorage`).
- Backups of earlier versions are kept in `backups/` as `player.pre-*.py` (never next to the working copy); delete them once a version has proven itself.
- Modal `<dialog>`s must stay `position:fixed` (CSS `dialog:modal`): never give `dialog` a bare `position:relative` (it made every modal open in the page flow and jump the page). Dialogs are height-limited and scroll inside, with their last `.row` sticky.
- Companion button text uses a literal `\n` for a line break.
- The player must keep running while Companion restarts; Companion reconnects by polling.
- Do not add a CPU-heavy task to the main tick; audio glitches are the failure that matters most.
- Docker Compose files, if any are added, are named `compose.yml`.
